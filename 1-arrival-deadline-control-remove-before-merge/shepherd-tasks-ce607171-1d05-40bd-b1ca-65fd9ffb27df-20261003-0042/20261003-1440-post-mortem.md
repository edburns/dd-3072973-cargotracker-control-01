## Section 8: Observations and Recommendations

### What worked well

- **Serial dependency control:** Every PR merged to the campaign base before the next dependent task completed.
- **Strong pre-review gates:** Stage 30 caught scope and formatting defects on [#10](https://github.com/edburns/dd-3072973-cargotracker-control-01/pull/10) before CCRA review.
- **High first-round quality:** Four of five PRs received zero-finding first reviews.
- **Effective review remediation:** The only actionable CCRA finding was fixed, thread-resolved, re-reviewed on the exact new head, and then merged.
- **End-to-end validation:** Later tasks included Open Liberty runtime, HTTP, browser, Ajax, persistence, reset, compatibility, and clean-shutdown evidence rather than relying only on unit tests.
- **Merge verification:** Stage 40 captured immutable merge SHAs, verified them on `origin/experiment/shepherd-control`, and confirmed issue closure.

### What could improve

- **Persist orchestration wait states:** The run directory cannot explain 77.8% of wall-clock time, including one 10h49 interval. The parent script should emit timestamped state transitions for assignment, CCA wait, Stage 30 completion, Stage 40 dispatch, and inter-task blocking.
- **Record structured review metrics:** Each Stage 40 artifact should persist review ID, head SHA, round number, open/resolved/new finding counts, and severity totals in a small machine-readable result. This would eliminate transcript inference.
- **Distinguish narrative observations from actionable findings:** CCRA output can contain “previously missed” prose while exposing zero open threads. Stage 40 should record whether each observation is actionable, already resolved, informational, or unmaterialized.
- **Expose token and credit telemetry:** Add aggregate input/output tokens and agent-specific credit fields to the terminal JSON result when available. Current `premiumRequests` and API duration are insufficient for cost comparison.
- **Persist remediation categories:** Stage 30 should emit structured counters for scope corrections, CI repair cycles, CCA re-engagements, and local validation failures. The [#10](https://github.com/edburns/dd-3072973-cargotracker-control-01/pull/10) recovery currently requires transcript inspection.
- **Compare control and treatment consistently:** Because lesson propagation was `off`, retain the same metrics schema for future `campaign` runs: completion rate, wall clock, active time, remediation count, review rounds, actionable findings, and unexplained wait time.

### Recommended priority

1. Add a parent-level JSONL event stream covering all inter-session wait states and dispatch decisions.
2. Add a per-stage machine-readable outcome file with timing, PR, review, finding, CI, merge, and usage fields.
3. Treat non-actionable CCRA narrative observations as an explicit review-gate state rather than silently folding them into “zero findings.”
4. Capture token and credit telemetry at session termination when the runtime exposes it.
